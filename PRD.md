## PRD: CLI_SORT — Telegram‑бот для сравнения сортировок

### 1. Обзор

- **Название продукта**: CLI_SORT  
- **Тип продукта**: Telegram‑бот  
- **Цель**: дать пользователю простой инструмент для экспериментов с различными алгоритмами сортировки и наглядного сравнения их производительности с встроенной сортировкой Python прямо из Telegram.

### 2. Цели и задачи

- **Основные цели**:
  - Предоставить удобный интерфейс в Telegram для выбора и запуска разных алгоритмов сортировки.
  - Показывать пользователю время работы алгоритма и сравнение со встроенной сортировкой.
  - Обеспечить корректность результатов сортировки (валидация по `sorted`).
  - Дать возможность легко повторно сортировать один и тот же массив разными алгоритмами.

- **Не цели (out of scope на текущий момент)**:
  - Графический интерфейс (GUI).
  - Распределённые/многопоточные вычисления.
  - Гарантированная работа с очень большими объёмами данных (миллионы элементов).

### 3. Целевая аудитория

- Студенты и начинающие разработчики, изучающие алгоритмы сортировки.
- Разработчики, которым нужен быстрый интерактивный инструмент для сравнения разных сортировок.
- Преподаватели и менторы, демонстрирующие поведение алгоритмов на примерах.

### 4. Пользовательские сценарии

- **Сценарий 1: Ручной ввод массива через Telegram**
  1. Пользователь открывает Telegram‑бот CLI_SORT и отправляет команду `/start`.  
  2. Бот кратко объясняет своё назначение и предлагает ввести массив.  
  3. Пользователь присылает массив (строкой целых чисел через пробел).  
  4. Бот формирует массив, предлагает список доступных алгоритмов и принимает выбор пользователя (командами или кнопками).  
  5. Бот выполняет сортировку, сравнивает время с системной сортировкой и отправляет результат в ответном сообщении.  
  6. Пользователь может повторно сортировать тот же массив, отправить новый или завершить общение.

- **Сценарий 2: Генерация случайного массива через Telegram**
  1. Пользователь открывает бота и отправляет команду (например, `/generate`) или следует подсказке бота.  
  2. Пользователь указывает минимум, максимум и количество элементов (одним или несколькими сообщениями — в зависимости от реализации).  
  3. Бот генерирует массив и отправляет его пользователю (при необходимости может сократить вывод).  
  4. Далее сценарий совпадает с выбором алгоритма сортировки и получением результата.

### 5. Функциональные требования

- **FR-1. Приветствие и стартовое сообщение**
  - Бот должен обрабатывать команду `/start`, отправлять приветствие и кратко объяснять назначение.  
  - Бот должен предлагать пользователю варианты: ввести массив вручную или сгенерировать его.

- **FR-2. Ввод массива через чат**
  - Пользователь может прислать последовательность целых чисел через пробел в одном сообщении.  
  - При некорректном вводе бот должен отправлять понятное сообщение об ошибке и просить повторить ввод с примером.

- **FR-3. Генерация массива**
  - Пользователь может задать минимальное значение, максимальное значение и количество элементов (через отдельную команду или диалог).  
  - В случае ошибок (нецелые значения, некорректный диапазон и т.п.) бот должен сообщать об ошибке и предлагать повторить ввод.

- **FR-4. Выбор доступных алгоритмов**
  - Список алгоритмов берётся из массива конфигурации (`ARRAY_OF_SORTS`).  
  - Для массивов с отрицательными значениями алгоритмы `counting sort` и `bucket sort` должны быть автоматически исключены из списка.  
  - Выбор алгоритма пользователем может происходить через команды или кнопки.

- **FR-5. Запуск сортировки и сравнение**
  - Бот должен:
    - скопировать текущий массив и передать его в выбранный алгоритм;  
    - замерить время выполнения алгоритма;  
    - отсортировать тот же массив с помощью встроенной функции `sorted` и замерить её время;  
    - убедиться, что результат алгоритма совпадает с результатом встроенной сортировки (за исключением специальной обработки для bucket, если требуется);  
    - отправить пользователю оба времени и итоговый отсортированный массив (при необходимости сократив вывод или обрезав его до разумного размера).
  - При некорректном результате должна выводиться понятная ошибка.

- **FR-6. Повторные действия**
  - После завершения сортировки бот должен позволять пользователю:
    - повторно отсортировать тот же массив другим алгоритмом;  
    - отправить новый массив или параметры генерации;  
    - завершить взаимодействие без дополнительных действий.

- **FR-7. Команда `/faq` и связь с документацией**
  - Бот должен обрабатывать команду `/faq` и отправлять краткий список ответов на самые частые вопросы (что делает бот, как передать массив, какие алгоритмы доступны, что делать при ошибке ввода).  
  - В ответе на `/faq` бот должен указывать, что расширенная техническая документация и полный список вопросов/ответов находится в файле `FAQ.md` репозитория проекта.

### 6. Нефункциональные требования

- **NFR-1. Производительность**
  - Замер времени должен происходить с достаточной точностью для демонстрации разницы между алгоритмами на массивах разумного размера (десятки–тысячи элементов).

- **NFR-2. Надёжность**
  - Бот не должен падать с необработанными исключениями при ошибках ввода пользователя; вместо этого должны отправляться человекочитаемые сообщения об ошибке.

- **NFR-3. Юзабилити (Telegram‑бот)**
  - Ответы бота должны быть краткими и понятными, без излишней технической информации.  
  - При ошибочном вводе бот должен отправлять подсказки с примерами корректного сообщения.  
  - Желательно использовать команды и/или кнопки, чтобы уменьшить количество ручного ввода.

### 7. Архитектура и модули

- **`sorts.py`**  
  - Описывает структуру данных `SortAlg` и набор поддерживаемых алгоритмов сортировки с их характеристиками (имя, сложность по времени/памяти, устойчивость, ссылка на функцию сортировки).

- **`sort_config.py`**  
  - Реализует генерацию массива, запуск алгоритма, замер времени и валидацию результата.  
  - Содержит функции, которые используются как ядро вычислений и переиспользуются Telegram‑ботом.

- **`tg_bot/bot.py`**  
  - Реализует Telegram‑обёртку вокруг логики сортировок.  
  - Отвечает за приём команд и сообщений из Telegram, преобразование их в параметры для функций ядра (`sort_config`, `sorts`) и отправку результатов пользователю.

### 8. Ограничения и допущения

- На текущем этапе работа ориентирована на использование через Telegram‑бота.  
- Ввод и вывод локализованы на русском языке.  
- Предполагается, что бот развёрнут на совместимой версии Python (3.x) в окружении, где установлен нужный набор зависимостей.  
- Для Telegram‑бота требуется действительный токен от BotFather; токен не должен храниться в открытом виде в репозитории.

### 9. Возможные направления развития

- Добавление новых алгоритмов сортировки и расширение метаданных по ним.  
- Поддержка сохранения результатов сортировок в файл (логирование).  
- Интеграция с ботами или web-интерфейсом для удалённого взаимодействия с функционалом сортировки.  
- Визуализация работы алгоритмов (анимация шагов) в GUI или web-приложении.
